# DTB B2 Prüfungstrainer

Тренажёр по билетам экзамена **telc Deutsch-Test für den Beruf B2**: Lesen 1–4, Beschwerde, Hören 1–4 с озвучкой голосом браузера, Telefonnotiz, Sprachbausteine 1–2, 68 тем форума, Sprechen Teil 3 и пробный экзамен с подсчётом баллов. Прогресс сохраняется в браузере (localStorage).

## Запуск на localhost

Нужен только Node.js (без установки пакетов):

```bash
cd ~/WebstormProjects/dtb-b2-trainer
npm start
```

Откроется http://localhost:5173. Остановить: `Ctrl+C`.
На Mac можно просто дважды нажать `start.command`. Другой порт: `PORT=8080 npm start`.

## Проверка писем ИИ (Schreiben)

Письма (Beschwerde, Forum) вы пишете сами, ИИ проверяет грамматику, построение предложений и уровень B2, показывает ошибки в тексте, более сильные формулировки и исправленный вариант. Для этого нужен ключ OpenAI (platform.openai.com). Ключ хранится только в переменной окружения, в код и в репозиторий он не попадает.

Локально:

```bash
OPENAI_API_KEY=sk-... npm start
```

На Vercel: Project → Settings → Environment Variables → `OPENAI_API_KEY` (при желании `OPENAI_MODEL`, по умолчанию `gpt-4o`), затем Redeploy. Страница обращается к собственным функциям `/api/ai` и `/api/status`, браузер ключа не видит. Без ключа письма можно писать и сравнивать с образцом.

## Кабинет преподавателя `/admin`

Отдельная страница для преподавателя: все ученики, которые сохраняют прогресс в Firebase. Видно имя и фамилию, дни занятий, число попыток и уникальных заданий, средний успех в процентах, ошибки к повтору, серию дней, достижения, активность по дням и динамику последних результатов. Есть поиск, фильтры, сортировка, карточка ученика и экспорт CSV.

Данные читает серверная функция `/api/admin/dashboard` по service account. Ключ остаётся на сервере и в браузер не попадает. Правила Firestore менять не нужно: service account имеет доступ к коллекции, а сама страница закрыта паролем.

### Vercel (продакшен)

1. Откройте [Firebase Console → Project settings → Service accounts](https://console.firebase.google.com/project/prufung-6e9b1/settings/serviceaccounts/adminsdk) → **Generate new private key**. Браузер скачает файл вида `prufung-6e9b1-firebase-adminsdk-xxxxx-xxxxxxxxxx.json`. Ключ должен быть от того же проекта, что и тренажёр (`prufung-6e9b1`).
2. Vercel → Project → Settings → Environment Variables:
   - `ADMIN_PASSWORD` — пароль для входа в `/admin` (придумайте сами, это не пароль Firebase);
   - `FIREBASE_SERVICE_ACCOUNT` — содержимое JSON-ключа целиком (можно одной строкой; также поддерживается base64 в `FIREBASE_SERVICE_ACCOUNT_B64`);
   - по желанию `ADMIN_SECRET` — стабильный ключ подписи cookie (иначе выводится из пароля).
3. Redeploy и откройте `https://b2-beruf-test.vercel.app/admin`.

Если Vercel не принимает многострочный JSON, положите ключ в base64:

```bash
base64 -i ~/Downloads/prufung-6e9b1-firebase-adminsdk-xxxxx-xxxxxxxxxx.json | tr -d '\n'
# вывод целиком -> FIREBASE_SERVICE_ACCOUNT_B64
```

Файл ключа не коммитьте: шаблоны `*-firebase-adminsdk-*.json`, `*adminsdk*.json`, `*service-account*.json` уже в `.gitignore`.

### Локально

```bash
ADMIN_PASSWORD=мой-пароль \
FIREBASE_SERVICE_ACCOUNT="$(cat key.json)" \
npm start
# http://localhost:5173/admin
```

Без `ADMIN_PASSWORD` сервер генерирует случайный пароль и печатает его в консоли при запуске. Без ключа Firebase страница `/admin` покажет пошаговую инструкцию. Если Firestore отвечает `403 Missing or insufficient permissions`, выдайте сервисному аккаунту роль **Datastore User** (или Firebase Admin) в Google Cloud IAM.

В кабинет попадают только ученики, которые в анкете «Данные участника» указали пароль: тогда прогресс синхронизируется в Firestore. Без пароля данные остаются в браузере и преподавателю не видны.

Сессия — HttpOnly-cookie на 8 часов; пароль в браузере не хранится. В кабинете показываются только имя, прогресс и активность. Дата рождения, адрес и остальные поля анкеты не читаются.

Интерфейс кабинета переключается между RU / EN / DE / FR / TR / AR / IT / UK (немецкий по умолчанию, как на основном сайте) и поддерживает тёмную/светлую тему. Тема и язык запоминаются в браузере.

Проверка: `npm test` (встроенный `node:test`, без зависимостей). Демо-данные не используются; тестовый набор лежит в `tests/` и на Vercel не выкладывается.

## Регистрация по e-mail и доступ по разрешению

- Ученик регистрируется по **e-mail и паролю** (имя и фамилия необязательны, нужны для рейтинга). Firebase сам отправляет письмо с подтверждением адреса, SMTP не нужен. Есть кнопка «Kennwort zurücksetzen».
- Старые аккаунты (имя + дата рождения + пароль) продолжают открываться: при первом входе к ним привязывается настоящий e-mail.
- Два разных доступа. **Допуск к тренажёру**: аккаунты, созданные до перехода на e-mail (до `ADMIT_BEFORE`, по умолчанию 2026-11-21 17:30 UTC), допущены автоматически; новые ждут кнопки **«Допустить»** в `/admin` (Firestore `admitted`). **ИИ** (платный) открывается отдельно кнопкой **«Открыть ИИ»** (Firestore `verified`) и никому не включается автоматически.
- Тренажёр новому ученику открывается только после «Допустить». До этого ученик видит экран «Ожидает разрешения» с контактом из переменной `VERIFY_CONTACT` (Vercel → Environment Variables, например `WhatsApp +49 …`). Проверка: `GET /api/access`.
- `ADMIN_EMAILS` (через запятую): e-mail владельца сайта. С подтверждённым адресом такой аккаунт всегда допущен, ИИ открыт, и в `/admin` можно войти этим e-mail и паролем от тренажёра как главный администратор. Пароль `ADMIN_PASSWORD` остаётся запасным входом.
- Если старый ученик (аккаунт без e-mail) не может войти: в `/admin` откройте его профиль → «Привязать e-mail для входа», затем на сайте «Забыли пароль?».
- Рейтинг показывает всех допущенных учеников (старые аккаунты сразу, новые после «Допустить»).
- Текст письма: Firebase Console → Authentication → Templates → Email address verification. Пример: «Здравствуйте! Вы зарегистрировались в тренажёре DTB B2 Beruf. Подтвердите e-mail по ссылке: %LINK%. Доступ к тренажёру открывается только участникам группы: свяжитесь с преподавателем по WhatsApp или по телефону и попросите разрешение на подключение.»

### Удаление посторонних

В `/admin` отметьте учеников галочками и нажмите «Удалить выбранных». Удаляются прогресс (`users/{uid}`), разрешение (`verified/{uid}`) и аккаунт Firebase Auth; резервная копия скачивается JSON-файлом. Для удаления аккаунтов service account нужна роль Firebase Authentication Admin (у ключа `firebase-adminsdk` она есть).

## Группы

- При регистрации ученик выбирает «Я ученик» и свою группу из списка одобренных групп, или «Я организатор группы» и пишет название новой группы.
- Заявка организатора попадает в `/admin` главного администратора (карточка «Группы»): «Одобрить», «Переименовать», «Отклонить/Удалить». После одобрения организатор допускается в тренажёр, группа появляется в списке при регистрации.
- Организатор входит в `/admin` → «Организатор группы» тем же e-mail и паролем, что в тренажёре, и видит только своих учеников: допуск, ИИ, удаление.
- Главный администратор (пароль `ADMIN_PASSWORD`) видит все группы и может открыть одну группу через выбор над таблицей.
- Рейтинг у каждого ученика только по его группе. Ученики без группы (зарегистрированные раньше) относятся к «Основной группе» (`MAIN`).
- Firestore: `groups/{code}` = {name, owner, email, status, at}.

## Режимы теста

- **Тренировка** — кнопки ответов активны, результат проверяется сразу после выбора. Это режим по умолчанию.
- **Экзамен** — ответы проверяются в конце, аудио звучит один раз.
- **Lernen** — правильные ответы уже отмечены, кнопки заблокированы: это режим просмотра, а не прохождения теста. Если вы попали в него случайно, нажмите кнопку **«▶ Тренировка»** рядом с подсказкой.
- Выбранный режим запоминается только до закрытия вкладки. При новом открытии сайт снова начинается с тренировки, поэтому «Lernen» больше не залипает навсегда.

## Повторные попытки

Ограничения по числу попыток нет: одно и то же задание можно проходить сколько угодно раз. После каждого завершения доступна кнопка «Пройти заново»; в шапке задания видно «Попыток: N», а `res.n` и `log` продолжают расти. Блок «Последние ошибки» показывает до 20 записей — это только список ошибок, а не лимит попыток.

## Перемешивание вариантов

При каждой новой попытке — после перезагрузки, кнопки «Пройти заново», нового варианта или пробного экзамена — варианты ответов и карточки соответствия перемешиваются, а правильный ответ пересчитывается. Номера заданий и связные тексты остаются на месте: иначе задание потеряло бы смысл. Внутри одной попытки порядок стабилен, поэтому переключение языка или режима не двигает варианты.

### Что сохраняется после теста

После завершения теста приложение пишет в `localStorage`, а у облачных учеников — в Firestore `users/{uid}.data`:

- `res` — результат по варианту: последний и лучший, максимум, число попыток, время;
- `nstat` — по каждому номеру задания: сколько раз ответ был верным и сколько всего;
- `wrong` — номера ошибок к повтору; при правильном ответе ключ удаляется;
- `log` — история попыток для активности и рейтинга.

Перетасовка меняет только порядок отображения. Проверка идёт по правильному ответу, поэтому в базу попадает фактическая правильность (например, `4 из 5` и `36: 1 из 2`), а не буква варианта, которая при следующей попытке будет другой.

## Тема, прогресс и рейтинг

- **Тёмная тема по умолчанию** на всём сайте. Переключатель — солнце/луна в шапке; выбор запоминается в `localStorage` (`dtb.theme`) и общий для тренажёра и кабинета. Светлую тему можно включить в любой момент.
- **«Мой прогресс»** (`#progress`) — дни занятий, уникальные задания и попытки, средний и лучший результат, ошибки к повтору, серия дней, график активности за 30 дней, разбивка по частям экзамена, достижения, последние результаты и ошибки. На главной есть компактная карточка прогресса со спарклайном.
- **«Рейтинг»** (`#leaderboard`) — соревнование учеников за неделю и за всё время. Показываются имя и первая буква фамилии, очки, попытки, дни, средний результат; топ-3 получают золото/серебро/бронзу. На главной виден топ-3 недели. Чтобы попасть в рейтинг, нужно сохранить прогресс в облаке (анкета → пароль от 6 символов), иначе результаты остаются только в браузере.
- Рейтинг читается публичной функцией `/api/leaderboard` (без пароля), но отдаёт только имя + инициал и агрегаты. Полные фамилии и остальные поля анкеты не публикуются.

## Голос для Hören

Лучший звук дают нейроголоса Microsoft (Katja, Amala, Conrad, Killian): они звучат как живые дикторы. Один раз запустите на своём компьютере (нужны интернет и Python 3):

```bash
python3 -m pip install edge-tts
npm run audio
```

Скрипт озвучит все диалоги и сообщения (около 500 коротких файлов, несколько минут) и сложит их в `assets/audio/`. Обновите страницу (Cmd+Shift+R): у каждого собеседника свой голос, в плеере будет надпись «диктор: нейроголос Microsoft». Если скрипт прервался, запустите его снова, он допишет недостающее.

Пока аудио нет, приложение читает голосами браузера (вкладка «Голос»: выбор голоса и скорость). Для Mac скачайте Anna / Petra / Markus (Premium): Системные настройки → Универсальный доступ → Устной контент → Управлять голосами → Немецкий.

## Ограничения

- Ответы заданий Lesen и Hören проверяются по заложенным ключам; при сомнении сверяйтесь с материалами курса.
- Кабинет `/admin` и рейтинг работают на Vercel (нужны serverless-функции `api/admin/*` и `api/leaderboard`). На GitHub Pages без функций они не откроются; прогресс и тема работают и без сервера.

## Subscriptions and trials

- «Допустить» in /admin starts one paid month on the trainer plan (5 €), «Открыть ИИ» one month on the AI plan (10 €).
  In a student's profile: «+1 месяц · 5 €», «+1 месяц с ИИ · 10 €», «Пробный 2/3 дня» (once per account), «Бессрочно».
- When the term ends the server closes the trainer and the AI by itself (Firestore `subs/{uid}`). Students without a
  `subs` document (everybody admitted before this feature) keep unlimited access.
- Letters: Vercel Cron calls `/api/cron/subs` once a day (08:00 UTC) and sends a reminder 3 days before the end of a
  paid month and a notice when a month or a trial has ended. Set in **one** Vercel project only:
  `CRON_SECRET` (any long random string), `RESEND_API_KEY` (resend.com), `MAIL_FROM` (e.g. `DTB Trainer <abo@your-domain>`,
  the domain verified in Resend). Without them access still closes on time, only the letters are not sent.

## PayPal

The waiting screen and the "subscription ended" screen show a PayPal.me button under each plan with the amount filled
in (5 € / 10 €) and a WhatsApp button with a ready message to send the receipt. The administrator checks the payment
and opens access by hand («Допустить» / «Открыть ИИ» / «+1 месяц»), which starts the month. The site does not check
payments itself. Optional Vercel setting: `PAYPAL_ME` (paypal.me name; default `RustemDzhuraiev`).
